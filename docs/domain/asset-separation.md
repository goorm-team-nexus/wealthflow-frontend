# 실자산/모의투자 데이터 분리 원칙

## 도메인 정의
- 실자산 도메인: 사용자가 실제로 보유하거나 직접 등록한 자산 정보를 다루는 영역.
- 모의투자 도메인: 서비스 내부의 가상 자금, 모의 주문, 모의 보유 종목, 모의 거래 내역을 다루는 영역.

## 분리 원칙
- 실자산과 모의투자의 데이터, 잔고, 상태, 비즈니스 로직은 분리한다.
- 두 도메인의 값은 API, DB, Service layer에서 섞지 않는다.
- 두 도메인은 홈, 리포트 같은 조회 화면에서만 나란히 표시할 수 있다.
- 실자산은 모의 거래, 랭킹, 환전 계산에 사용하지 않는다.
- 모의투자는 실제 자산 계산에 사용하지 않는다.

## 금지 예시
- 실자산 잔고를 모의 매수 가능 금액으로 사용하는 것.
- 모의투자 평가 금액을 실제 총자산에 합산하는 것.
- 하나의 API 응답이나 Service 로직에서 두 도메인의 잔고를 합산해 저장하는 것.
- 실자산 데이터를 모의투자 랭킹 기준으로 사용하는 것.
- 모의 환전 결과를 실제 자산 상태에 반영하는 것.

## 허용 예시
- 홈 화면에서 실자산 요약과 모의투자 요약을 별도 카드로 표시하는 것.
- 리포트 화면에서 두 도메인의 지표를 분리된 섹션으로 나란히 보여주는 것.
- 같은 사용자 화면에서 실자산 조회 결과와 모의투자 조회 결과를 각각 독립적으로 요청해 표시하는 것.
- 두 도메인의 타입, 상태, 계산 로직을 별도로 유지하는 것.

## 설계 상태
- API 상세 설계는 아직 확정하지 않는다.
- DB 상세 설계는 아직 확정하지 않는다.
- 구체적인 table name, endpoint, schema는 별도 문서에서 확정한다.
