# 보안 주의사항

## 기본 원칙

- secret, credential, token은 코드, 문서, 로그, 이슈, PR, 채팅에 노출하지 않는다.
- 인증과 인가 흐름은 합의된 설계와 contract를 따른다.
- 인증과 인가 정책을 임의로 우회하거나 변경하지 않는다.
- 보안 관련 요구사항이 불명확하면 구현 전에 확인한다.

## 인증 정보 처리

- JWT와 인증 정보는 필요한 범위와 기간 안에서만 사용한다.
- JWT payload는 누구나 읽을 수 있는 정보로 간주하고 민감정보를 포함하지 않는다.
- 인증 정보 저장, 전달, 만료, 갱신 방식은 프로젝트에서 정한 흐름을 따른다.
- 토큰 검증, 권한 판단, 세션 상태 변경은 신뢰할 수 있는 경계에서 처리한다.

## 환경 변수 사용

- 환경별 설정값과 민감한 설정은 환경 변수로 관리한다.
- 환경 변수 이름은 목적을 명확히 표현하고, 값 자체를 문서에 기록하지 않는다.
- 로컬, 개발, 운영 환경의 설정은 분리한다.
- 기본값을 둘 때 민감정보나 운영 설정이 포함되지 않도록 한다.

## 로그와 모니터링

- 로그에는 secret, credential, token, API key, 개인 식별 정보, 인증 헤더를 출력하지 않는다.
- 오류 메시지는 문제 파악에 필요한 수준으로 제한하고 민감한 내부 상태를 노출하지 않는다.
- 디버깅을 위해 민감정보를 임시로 출력한 경우 작업 완료 전에 제거한다.

## 외부 API Key 관리

- 외부 API key는 환경 변수나 승인된 secret 관리 수단으로 관리한다.
- 외부 API key의 권한은 필요한 최소 범위로 제한한다.
- 외부 API key는 노출 가능성이 있는 클라이언트 코드, 번들, 정적 파일에 포함하지 않는다.
- 키가 노출되었거나 의심되는 경우 즉시 폐기하고 재발급한다.

## 클라이언트 보안

- 클라이언트에서 secret을 보관하거나 처리하지 않는다.
- 브라우저에 전달되는 값은 사용자와 제3자가 볼 수 있다고 가정한다.
- 클라이언트의 화면 제어만으로 권한을 보장하지 않는다.
- 민감한 연산과 권한 판단은 신뢰할 수 있는 서버 측 경계에서 수행한다.
